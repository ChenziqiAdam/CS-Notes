- Limitations
	- Overflow / Underflow
		- Overflow: Exponent is larger than can be represented
		- Underflow: Negative exponent is larger than can be represented
	- Rounding: Result runs off the end of the Significand
	![[Pasted image 20250111194057.png]]
	- Floating Point Gaps
		- Q. Does adding 0x00000001 always add the same value to the floating point number?
			- NO. it's value depends on the exponent field.
		- Thus floating points are quite different from the decimal number representations.
	- Floating Point addition is NOT associative.
		- e.g. Small + Big + Small != Small + Small + Big
		- Due to *rounding errors*: FP approximates results because it only has 23 bits for Significand.
	- FP cannot represent all integers due to gaps.
		- The number of floats between 1 and 2 is bigger than the number of floats between 2 and 3.
	- Example: Suppose Big = 2<sup>60</sup>, Tiny = 2<sup>-15</sup>, BigNeg = -Big
		- (Big \* Tiny) \* BigNeg == (Big \* BigNeg) \* Tiny
			- is TRUE as long as Big * BigNeg doesn't overflow.
		- (Big + Tiny) + BigNeg == (Big + BigNeg) + Tiny
			- evaluates to 0 != Tiny, which is FALSE as long as Tiny is at least 224 times smaller than Big.
