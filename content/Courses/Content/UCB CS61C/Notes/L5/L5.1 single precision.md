- Goals
	- Standard arithmetic for reals for all computers
		- Important because computer representation of real numbers is approximate. Want same results on all computers
	- Keep as much precision as possible
	- Help programmer with errors in real arithmetic
		- +00,-00, Not-A-Number (NaN), exponent overflow, exponent underflow, +/- zero
	- Keep encoding that is somewhat compatible with two's complement
		- E.g., +0 in Fl. Pt. is 0 in two's complement
		- Make it possible to sort or compare numbers without understanding floating-point
- Floating Point Encoding: **Single Precision**
	- Normalized, Base 2 scientific notation: +1.xxx...x<sub>two</sub>x2<sup>yyy...y</sup>two
	- Split a *32-bit* word into 3 fields:
		- **S** represents Sign (1 is negative, 0 positive): 1 bit
		- **Exponent** represents y's: 8 bits
		- **Significand** represents x's: 23 bits
	- Q. For the exponent field, why use **biased notation**?
		- Remember that we want floating point numbers to look small when their actual value is small.
			- We don't like how in 2's complement, -1 looks bigger than 0. 
			- Bias notation preserves the linearity of value.
		- Recall that only the first bit denotes sign.
			- Thus, floating point resembles sign and magnitude.
	- Use biased notation but with bias of -127
		- Read exponent field as unsigned, add the bias (+ (-127) = -127) to get the actual exponent
		- Exponent Field: 0 (00000000<sub>two</sub>) to 255 (11111111<sub>two</sub>)
		- Actual exponent: -127 (00000000<sub>two</sub>) to 128 (11111111<sub>two</sub>)
	- To encode in biased notation, subtract the bias (- (-127) = +127) then encode in unsigned:
		- If we had 2<sup>1</sup>, exp = 1 => 128 => 10000000<sub>two</sub>
		- 2<sup>127</sup>: exp = 127 => 254 > 11111110two
- What does Significand mean?
	- Think of it as: (1 + Value of Significand)
	- Since the Significand represents all the negative powers of 2, its total value is always < 1
	- Example: 1.0101<sub>two</sub> = 1 + 2<sup>-2</sup> + 2<sup>4</sup> = 1.3125
- **Example**: Representing the decimal number 12.5 in Single-Precision
	1. **Determine the sign:** 12.5 is positive, so the sign bit is 0.
	2. **Convert the absolute value to binary:**
	    - Integer part: 12<sub>10</sub>​=1100<sub>2</sub>​
	    - Fractional part: 0.5<sub>10​</sub>=0.1<sub>2</sub>​ (0.5×2=1.0)
	    - So, 12.5<sub>10​</sub>=1100.1<sub>2</sub>​.
	3. **Normalize the binary number:** 
		- Move the binary point so there is only a '1' to its left. 
		- 1100.1<sub>2</sub>​=1.1001<sub>2</sub>​×2<sup>3</sup>
	4. **Determine the exponent:** 
		1. The actual exponent is 3. 
		2. Add the bias: Exponent field value = Actual Exponent + Bias = 3+127=130<sub>10</sub>​. 
		3. Convert the exponent field value to 8-bit binary: 130<sub>10</sub>​=1000 0010<sub>2</sub>​.
	5. **Determine the significand (fraction):** 
		- The normalized number is 1.1001<sub>2</sub>​×2<sup>3</sup>. 
		- The '1' before the binary point is _implied_ (for normalized numbers). 
		- The fraction part is the bits _after_ the binary point: 1001. 
		- The significand field has 23 bits. 
		- Pad the fraction with zeros to the right: 1001 0000000000000000000<sub>2</sub>​.
	6. **Assemble the bits:**
	    - Sign bit: 0
	    - Exponent: 1000 0010
	    - Significand: 1001 0000 0000 0000 0000 000
	    - Putting it together (often written with spaces for readability): 0 10000010 10010000000000000000000<sub>2</sub>​
