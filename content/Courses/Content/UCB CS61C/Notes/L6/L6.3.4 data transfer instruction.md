- **Data Transfer**
	- Data Transfer instructions are between registers (Datapath) and Memory
		- Allow us to fetch and store operands in memory
		- Store: register TO memory
		- Load: register FROM memory
	- Instruction syntax for data transfer:
		`memop reg, off (bAddr)`
		- `memop` = operation name ("operator")
		- `reg` = register for operation source or destination
		- `bAddr` = register with pointer to memory ("base address")
		- `off` = address offset (immediate) in bytes ("offset")
		- Access memory at address `bAddr+off`
	- Reminder: A register holds a word of raw data (no type) 
		- Make sure to use a register (and offset) that point to a valid memory address
- Memory is **Byte-Addressed**
	- What was the smallest data type we saw in C?
		- A char, which was a byte (8 bits)
		- Everything in multiples of 8 bits (e.g. 1 word = 4 bytes)
	- Memory addresses are *indexed by bytes*, not words.
		- Word addresses are 4 bytes apart
		- Word address is same as first byte
		- Addresses must be multiples of 4 to be "word-aligned"
	- Pointer arithmetic not done for you in assembly
		- Must take data size into account yourself
	- Load Word `lw`
		- Takes data at address `bAddr+off` FROM memory and places it into `reg`
	- Store Word `sw`
		- Takes data in `reg` and stores it TO memory at address `bAddr+off`
	- Example usage: address of `int array[]` -> `s3`, value of `b` -> `s2` 
		`array[10] = array[3] + b;`
		```RISCV
		lw  t0,12(s3) # t0=A[3]
		add t0,s2,t0  # t0=A|3]+b
		sw  t0,40(s3) # A[10]=A[3]+b
		```
		- Note: the size of `int` is 4 bytes on a 32-bit system.
- RICS-V is ***Little Endian***.
	- **Little Endian** and **Big Endian** are two different ways to store data in memory when representing multi-byte data types like integers.
		- Big Endian: Most-significant byte at least address of word
			- word address = address of most significant byte
		- Little Endian: Least-significant byte at least address of word
			- word address = address of least significant byte
- All base RICSV instructions **sign extend** when needed.
	- **Sign Extension**: We want to represent the same number using more bits than before
		- **Sign Extend**: Take the most-significant bit and copy it to the new bits
			- e.g. `0b 11 = 0b 1111`
		- **Zero/One Pad**: Set the new bits with one/zero.
			- Zero Pad: `0b 11 = 0b 0011`
			- One Pad: `0b 11 = 0b 1111`
- `lb`/`sb` (load/store byte) utilize the least significant byte of the register
	- On `sb`, upper 24 bits are ignored
	- On `lb`, upper 24 bits are filled by sign-extension
	- For example, let `s0 = 0x00000180`:
		```
		| 0x00 | 0x00 | 0x01 | 0x80 |
		   3      2      1      0
		```
		```
		lb s1,1(s0) # s1=0x00000001
		lb s2,0(s0) # s2=0xFFFFFF80
		sb s2,2(s0) # *(s0)=0x00800180
		```
		- `s0 = 0x00000180` means that the memory address `s0` holds the value `0x00000180` in hexadecimal.
		- The value `0x00000180` is split into bytes:
			- Byte 0 (most significant byte) = `0x00`
			- Byte 1 = `0x00`
			- Byte 2 = `0x01`
			- Byte 3 (least significant byte) = `0x80`
		- Each byte is represented as a two-digit hexadecimal number.
- Half-Word Instructions
	- `lh reg, off (bAddr)` "load half" and `sh reg, off (bAddr)` "store half"
		- On `sh`, upper 16 bits are ignored
		- On `lh`, upper 16 bits are filled by sign-extension
- Unsigned Instructions
	- `lhu reg, off (bAddr)` "load half unsigned"
	- `lbu reg, off (bAddr)` "load byte unsigned"
		- On `l(b/h)u`, upper bits are filled by zero-extension
