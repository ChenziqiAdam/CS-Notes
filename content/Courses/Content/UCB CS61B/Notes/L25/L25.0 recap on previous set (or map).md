- So far we’ve seen three different efficient implementations of a Map (or Set):
	- Binary Search Tree.
	- 2-3 Tree / 2-3-4 Tree / B-Tree.
	- Red Black Tree.
- These “search tree” data structures support very fast insert, remove, and delete operations for arbitrary amounts of data.
	- Requires that data can be compared to each other with some total order.
	- We used the “Comparable” interface as our comparison engine.
- There are other more powerful operations we might want to include in a Set.
	For example:
	- `select(int i)`: Returns the ith smallest item in the set
		- `{1, 4, 5, 6, 9, 11, 14, 17, 20}`
		- `select(0)`: 1
		- `select(3)`: 6
	- `rank(T x)`: Return the "rank" of `x` in the set (opposite of `select()`)
		- `{1, 4, 5, 6, 9, 11, 14, 17, 20}`
		- `rank(1)`: 0
		- `rank(6)`: 3
	- `subSet(T from, T to)`: Returns all items between from and to
		- `{1, 4, 5, 6, 9, 11, 14, 17, 20}`
		- `subSet(4, 12)`: {4, 5, 6, 9, 11}
	- `nearest(T x)`: Returns the value closest to `x`.
		- `{1, 4, 5, 6, 9, 11, 14, 17, 20}`
		- `nearest(8)`: Returns 9.
- It turns out that a BST can efficiently support the `select`, `rank`, `subSet`, and `nearest` operations.
	- Q. how to implement `nearest`?
	- Search for N and record closest item seen!
		- If found, it is N
		- If not found, it is the number recorded, i.e. the closest item seen.
- However, so far we’ve only discussed “one dimensional data”. 
	That is, all data could be compared under some total order.
	- 1 < 3 < 6 < 9 < 15
	- “cat” < “doghouse” < “if” < “zebra” -> \[using alphabetical order]
	- “if” < “cat” < “zebra” < “doghouse” -> \[using string length]
- But not all data can be compared along a single dimension, there is multidimensional data!
