- **Partition Sort** (a.k.a. **Quicksort**)
	- Partition on leftmost item
	- Quicksort left half
	- Quicksort right half
	See [CS61B quick sort demo](https://docs.google.com/presentation/d/1QjAs-zx1i0_XWlLqsKtexb-iueao9jNLkN-gW9QxAD0/edit?usp=sharing).
- Runtime: For most common situations, it is empirically the **fastest** sort.
	- Theoretical analysis:
		- Best case: Θ(N log N)
			![[Pasted image 20241009200306.png]]
		- Worst case: Θ(N<sup>2</sup>)
			![[Pasted image 20241009200328.png|200]]
	- Compare this to Mergesort.
		- Best case: Θ(N log N)
		- Worst case: Θ(N log N)
- Q. Recall that Θ(N log N) vs. Θ(N<sup>2</sup>) is a really big deal. So how can Quicksort be the fastest sort empirically? 
	Because on average (randomly chosen array case) it is Θ(N log N).
