- The key idea from our previous sorting lecture: Sorting requires Ω(N log N) compares in the worst case.
	- Thus, the ultimate comparison based sorting algorithm has a worst case runtime of Θ(N log N).
- Q. From an asymptotic perspective, that means no matter how clever we are, we can never beat Merge Sort’s worst case runtime of Θ(N log N). But what if we do not base on comparison?
- Example #1: Sleep Sort (for integers) (not good in practice)
	- For each integer x in array A, start a new program that:
		- Sleeps for x seconds.
		- Prints x.
		All start at the same time.
	- Runtime: N + max(A) (theoretically)
	- On real machines, scheduling execution of programs must be done by an operating system. In practice requires list of running programs sorted by sleep time.
