- Example code:
	- Works
		```Java
		public void addLast(int x) {
			if (size == items.length) {
				int[] a = new int[size + 1];
				System.arraycopy(items, 0, a, 0, size);
				items = a;
			}
			items[size] = x;
			size += 1;
		}
	```
	- Much Better
		```Java
		private void resize(int capacity) {
			int[] a = new int[size + 1];
			System.arraycopy(items, 0, a, 0, size);
			items = a;
		}
		
		public void addLast(int x) {
			if (size == items.length) {
				resize(size + 1);
			}
			items[size] = x;
			size += 1;
		}
	```
- **Breaking the code down to smaller parts makes it more readable and easier to text and debug.**
	- Testing is vital!
- Runtime and Space Usage Analysis
	- Q. suppose now have a full array of size 100. If call `addLast` until `size`=1000, how many total array memory boxes will need?
		101+102+103+...+1000 = 500000
		- Poor Performance!
	- Sol: **Geometric(几何的) Resizing**
		- Linear resizing: unusably bad!
			```Java
			public void addLast(int x) {
				if (size == items.length) {
					resize(size + RFACTOR);
				}
				items[size] = x;
				size += 1;
			}
```
		- Geometric resizing: surprisingly great!
			```Java
			public void addLast(int x) {
				if (size == items.length) {
					resize(size * RFACTOR);
				}
				items[size] = x;
				size += 1;
			}
```
- Memory Efficiency
	An AList should not only be efficient in time, but also efficient in space.
	- Define the "usage ratio" R: `R = size / items.length`
	- Typical solution: half array size when R < 0.25
