- **Selection Sort**
	1. Find smallest item.
	2. Swap this item to the front and ‘fix’ it.
	3. Repeat for unfixed items until all items are fixed.
	- Θ(N<sup>2</sup>) seems inefficient: We look through entire remaining array every time to find the minimum. 
- ***Heapsort***: Instead of rescanning entire array looking for minimum, maintain a heap so that getting the minimum is fast!
	- We'll use a max-oriented heap (reasons come later).
	- **Naive heapsorting**: 
		- Insert all items into a max heap, and discard input array. Create output array.
		- Repeat N times:
			- Delete largest item from the max heap.
			- Put largest item at the end of the unused part of the output array.
	- Overall runtime is O(N log N) + Θ(N) + O(N log N) = **O(N log N)**
		- Getting items into the heap O(N log N) time.
		- Selecting largest item: Θ(1) time.
		- Removing largest item: O(log N) for each removal.
	- Memory usage is Θ(N) to build the additional copy of all of our data.
		- This can be eliminated with some fancy trickery.
- ***In-place Heapsort***: treat input array as a heap!
	- Rather than inserting into a new array of length N + 1, use a process known as “bottom-up heapification” to convert the array into a heap.
		To bottom-up heapify, just sink nodes in reverse level order.
		- Sink nodes in reverse level order: sink(k)
		- After sinking, guaranteed that tree rooted at position k is a heap.
	- Avoids need for extra copy of all data.
	- Once heapified, algorithm is almost the same as naive heap sort.
	- See [CS61B in-place heapsort demo](https://docs.google.com/presentation/d/1SzcQC48OB9agStD0dFRgccU-tyjD6m3esrSC-GLxmNc/edit?usp=sharing).
- Overall runtime of in-place heapsort is **O(N log N)**.
	- Bottom-up heapification is N sink operations, each taking no more than O(log N) time, so overall runtime for heapification is O(N log N).
- Memory (space) complexity: **Θ(1)**.
	- The algorithm is **in-place**, i.e. reusing the same array.
	- The only extra memory we need is a constant number instance variables, e.g. size.
