- Graph Representation 1#: Adjacency Matrix
	- `G.adj(2)` would return an iterator where we can call `next()` up to two times
		- `next()` returns 1
		- `next()` returns 3
	- Total runtime to iterate over all neighbors of v is Θ(V).
		- Underlying code has to iterate through entire array to handle `next()` and `hasNext()` calls.

	- Runtime (V is the number of vertices, and E is the total number of edges)
		- Iterate v's neighbors: Θ(V)
		- Print: Θ(V<sup>2</sup>)
- Graph Representation 2#: Edge Sets: Collection of all edges.
	```Yaml
		1
	  / |
	 0  |
	  \ |
	    2 
```
	- Uncommon but useful in particular cases
	- Example: HashSet\<Edge>, where each Edge is a pair of ints.
		`{(0, 1), (0, 2), (1, 2)}`
- Graph Representation 3#: Adjacency lists
	```Yaml
		1
	  / |
	 0  |
	  \ |
	    2 
```
	- Common approach: Maintain array of lists indexed by vertex number.
	- Most popular approach for representing graphs.
	![[Pasted image 20240909113111.png]]
	- Runtime (V is the number of vertices, and E is the total number of edges)
		- Iterate v's neighbors: Ω(1)
		- Print: Θ(V + E)
- Graph Printing Runtime: 
	How to interpret: No matter what “shape” of increasingly complex graphs we generate, as V and E grow, the runtime will always grow exactly as Θ(V + E).
	```Java
	for (int v = 0; v < G.V(); v += 1) {
	    for (int w : G.adj(v)) {
	        System.out.println(v + “-” + w);
	    }
	}
```
	- Example shape 1: Very sparse graph where E grows very slowly, e.g. every vertex is connected to its square: 2 - 4, 3 - 9, 4 - 16, 5 - 25, etc.
		- E  is Θ(sqrt(V)). Runtime is Θ(V + sqrt(V)), which is just Θ(V).
	- Example shape 2: Very dense graph where E grows very quickly, e.g. every vertex connected to every other.
		- E is Θ(V2). Runtime is Θ(V + V2), which is just Θ(V2).
- Graph Representations Runtime

| Representations  | `addEdge(s, t)` | `for(w : adj(v))` | `print()`        | `hasEdge(s, t)` | Space used       |
| ---------------- | --------------- | ----------------- | ---------------- | --------------- | ---------------- |
| adjacency matrix | Θ(1)            | Θ(V)              | Θ(V<sup>2</sup>) | Θ(1)            | Θ(V<sup>2</sup>) |
| list of edges    | Θ(1)            | Θ(E)              | Θ(E)             | Θ(E)            | Θ(E)             |
| adjacency list   | Θ(1)            | Θ(1) to Θ(V)      | Θ(V+E)           | Θ(degree(v))    | Θ(V+E)           |

- In practice, adjacency lists are most common.
	- Many graph algorithms rely heavily on `adj(s)`.
	- Most graphs are sparse (not many edges in each bucket)
- Bare-Bones Undirected Graph Implementation
	```Java
	public class Graph {
		private final int V;  private List<Integer>[] adj;
		
		public Graph(int V) {
	    	    this.V = V;
	    	    adj = (List<Integer>[]) new ArrayList[V]; // Cast: cannot create array of anything involving generics
	    	    for (int v = 0; v < V; v++) {
	             adj[v] = new ArrayList<Integer>();
	         }
		} 
	
		public void addEdge(int v, int w) {
	         adj[v].add(w);   adj[w].add(v);
		}
	
		public Iterable<Integer> adj(int v) {
	        return adj[v];
		}
	}
```
