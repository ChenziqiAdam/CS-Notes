- ***Overriding***: if a "subclass" has a method with the exact same signature as in the "superclass", then the subclass *overrides* the method.
	- Example: `AList` overrides `addLast()` method
		```Java
		public interface List61B<Item> {
			public void addLast(Item y);
			...
		}
		
		public class Alist<Item> implements List61B<Item> {
			...
			@Override
			public void addLast(Item x) {
				...
			}
			...
		}
```
		- `@Override`: the only effect of the tag is that the code won't compile if it is not actaully an overriding method. But this just a optional reminder, i.e. the subclass will still overrides the method without `@Override`.
	- Q. why use `Override`?
		- **Main reasion**: protects against typos.
			- If `@Override` but the method isn't actually overriding anything, there will be a compile error.
		- Reminds programmer that method definition came from somewhere higher up in the ingeritance hierarchy.
