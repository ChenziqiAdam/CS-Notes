- Each variable in Java has two types!
	- ***Static type*** (a.k.a. *compile-time type*)
		- This is the type declared at **declaration**.
		- Never changes!
	- ***Dynamic type*** (a.k.a. *run-time type*)
		- This is the type specified at **instantiation** (e.g. when using `new`)
		- Equal to the type of the object being pointed at.
- ***Dynamic Method Selection*** (*DMS*) for overridden methods
	- Suppose we call a method of an object using a variable with X (static type) and Y (dynamic type), then if Y overrides the method, Y's method is used instead.
	- Another way to think about *DMS* is as a two-step process
		step 1 happens at compile time, and step 2 happens at runtime.
		- At compile time: we determine the **signature S** of the method to be called.
			- S is decided using **ONLY static types**.
		- At runtime: the dynamic type of the **invoking object** uses its method with this exact signature S.
			- By "invoking object", we mean the object whose method is invoked.
- Q. Which method signature will be used for each call?
	- Rule 1: The signature is decided using **ONLY static types**.
	- The signature is the method name and the number and type of its parameters.
	```Java
	public interface Animal {
		default void greet(Animal a)
		default void sniff(Animal a)
		default void praise(Animal a)
	}

	public class Dog implements Animal {
		void sniff(Animal a)
		void praise(Dog a)
	}
	```
	```Java
	animal a = new Dog();
	Dog d = new Dog();
	a.greet(d);    // greet(Animal a)
	a.sniff(d);    // sniff(Animal a)
	d.praise(d);   // praize(Dog a)
	a.praise(d);   // praise(Animal a)
```
- DMS:
	1. Check whether there is a function satisfies exactly the same signature in static type class.
	2. Since it also has dynamic type, it's better to see whether where exists the same signature function in dynamic type class.
