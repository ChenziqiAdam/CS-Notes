### Binary

- Union $\cup$ (UNION)
	- Two input relations, must be compatible:
		- Same number of fields
		- Fields in corresponding positions have same **type**
	- SQL Expression: UNION
	- Union v.s. Union ALL
		- Union: remove duplicates
		- Union ALL: keep duplicates
- Set Difference $-$ (EXCEPT)
	- Same as with union, both input relations must be compatible.
	- SQL Expression: EXCEPT
	- EXCEPT v.s. EXCEPT ALLL
		- EXCEPT returns the distinct rows from the first query that are not present in the second query.
		- EXCEPT ALL returns all rows from the first query that are not present in the second query, including duplicates.
	- Note: Set Difference is not communicative
- Cross-Product $\times$
	- $R1 \times S1$: Each row of $R1$ paired with each row of $S1$
		![[Pasted image 20250630162124.png|600]]
		- $|R1| * |R2|$ rows in result
		- No need for compatability
		- NO duplicates generated
- Renaming $\rho$
	- Renames relations and their attributes
	- Note that relational algebra doesn't require names.
		- We could just use positional arguments.
	![[Pasted image 20250630162437.png]]

### Compound

- Intersection $\cap$ (INTERSECT)
	- Same as with union, both input relations must be compatible.
	- SQL Expression: INTERSECT
	- Implementation: $S1 \cap S2 = S1 - (S1 - S2)$
		![[Pasted image 20250630162644.png]]
- Join $\bowtie$
	- Joins are compound operators (like intersection):
		- Generally, $\bowtie_{\theta}(R \times S)$
	- Hierarchy of common kinds:
		- Theta Join $\bowtie_{\theta}$: join on logical expression $\theta$
			- Equi-Join: theta join with theta being a conjunction of equalities
				- Natural Join ($\bowtie$): equi-join on all matching column names
	- Note: Join avoids using cross-product as it is really expensive
