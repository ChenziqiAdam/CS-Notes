- Features of B+ Tree
	- Similar to ISAM
		- Same interior node structure
			- <Key, Page Ptr> pairs with same key invariant
		- Same search routine
	- Dynamic Tree Index
		- Always Balanced
		- Support efficient insertion/deletion
			- Grows at root not leaves!
	- Note: '+' is a variant of B tree, which stores data entries in the leaves only.

- Insertion Algorithm Sketch
	1. Find the correct leaf L.
	2. Put data entry onto L.
		- If L has enough space, done!
		- Else, must split L (into L and a new node L2)
			- Redistribute entries evenly, copy up middle key
			- Insert index entry pointing to L2 into parent of L.
	- Step 2 can happen recursively
		- To split index node, redistribute entries evenly, but push up middle key. (Contrast with leaf splits)
	- Splits "grow" tree: root split increases height.
		- Tree growth: gets wider or one level taller at top.
	- Notice that the root was split to increase the height
		- Grow from the root not the leaves
		- All paths from root to leaves are equal lengths
- Splitting a Leaf Algorithm Sketch
	- Start with full leaf (2d) entries (let d = 2)
		- Add the 2d+1<sup>th</sup> entry
	- Split into leaves with (d, d+1) entries
		- **Copy** key up to parent
		- The reason for this is that in B+ trees, data entries are all stored in the leaves only. The one copied up is just the routing key.
- Splitting an Inner Node Algorithm Sketch
	- Start with full interior node (2d) entries
		- Add the 2d+1<sup>th</sup> entry
	- Split into nodes with (d, d) entries
		- **Push** key up to parent
		- As routing key is not needed in child (inner node)
- Deletion (Simple)
	- Simple means that occupancy invariant often not enforced
		- Efficient and simple
	- Just delete leaf entries ad leave space
	- If new inserts come, great
	- If page becomes completely empty, can delete
		- Parent may become underfull
		- That is ok too
