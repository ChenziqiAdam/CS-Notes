- **ISAM** (**Indexed Sequential Access Method**), i.e. simple sorted (`key`, `page id`) file
	- Step 1: Sort heap file & leave some space
		- Pages physically stored in logical order (sequential access)
		- Do we need "next" pointers to link pages?
			- No. Pages are physically sorted in logical order
	- Step 2: Build the index data structure
		- Note: why not just use binary search in this heap file?
			- 2 is too small -> deep tree -> lots pf I/Os
		- Build a **high fan-out** (高输出) search tree
			- No record data
			- Binary search in the key file. Better!
			- Complexity: Still binary search, just a constant factor smaller input
			- Recursively "index" key file (build a search file for the search file)
		- Key Invariant:
			- All tuples in range K<sub>L</sub> <= K < K<sub>R</sub> are in tree P<sub>L</sub>
		- Complexity: O(log<sub>F</sub>(#Pages)), F is the fan
	![[Pasted image 20250616095237.png]]
	- Optimization: no need for the left most key
		![[Pasted image 20250616111456.png]]
	- Disk Layout: all in a single file, data pages first
		![[Pasted image 20250616111607.png]]
	- Summary
		- Fast sequential scan
		- High Fan-out
		- DO **NOT** support insertion/deletion!
	- e.g. for insertion
		- Find location
		- Place in data page
		- Add overflow page if necessary (flaw!)
