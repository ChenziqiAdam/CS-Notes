- Idea: 
	- Many times we don't require order
	- e.g. removing duplicates
	- e.g. forming groups
	- Often just need to rendezvous matches
- Hashing does this. 
	- Q. But how to do it out-of-core?
	- Divide and Conquer!
- Streaming Partition (divide): Use a hash function **h<sub>p</sub>** to stream records to disk partitions
	- All matches rendezvous in the same partition.
	- Each partition a mix of values
	- Streaming algorithm to create partitions on disk:
		- "Spill" partitions to disk via output buffers
	![[Pasted image 20250701164215.png|400]]
- ReHash (conquer): Read partitions into RAM hash table one at a time, using hash f'n **h<sub>r</sub>**
	- Each bucket contains a small number of distinct values
	![[Pasted image 20250701164334.png|400]]
- Then read out the RAM hash table buckets and write to disk
	- Ensuring that duplicate values are contiguous (in the same bucket)
	![[Pasted image 20250701164653.png]]
- Cost = 2\*N\*(# of passes) = 4\*N IO's (includes initial read and final write)
- Q. How big of a table can we hash in two passes?
	- B-1 "partitions" result from Pass 1
	- Each should be no more than B pages in size
	- Answer: B\*(B-1).
		- We can hash a table of size N pages in about $B = \sqrt{N}$ space
	- Note: assumes hash function distributes records evenly!
- Q. Have a bigger table? 
	- Recursive partitioning!
