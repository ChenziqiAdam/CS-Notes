- **VCS: Vision Control System**
- Git terminology
	```mathematica
	<root> (tree)
	|
	+- foo (tree)
	|  |
	|  + bar.txt (blob, contents = "hello world")
	|
	+- baz.txt (blob, contents = "git is wonderful")
```
- Git snapshot:
	```markdown
	o <-- o <-- o <-- o <---- o  (main)
            ^            /
             \          v
              --- o <-- o  (bugfix branch)
```
	- Each `o` sorresponds to individual commit (snapshot).
	- Commits in Git are immutable.
- Data model (not Python but pseudocode)
	```mathematica
	// a file is a bunch of bytes
	type blob = array<byte>
	
	// a directory contains named files and directories
	type tree = map<string, tree | blob>
	
	// a commit has parents, metadata, and the top-level tree
	type commit = struct {
	    parents: array<commit>
	    author: string
	    message: string
	    snapshot: tree
	}
```
- Objects and Content-Addressing (also pseudocode)
	```mathematica
	// an object is a blob, tree, or commit
	type object = blob | tree | commit

	// all objects are content-addressed by their SHA-1 hash
	objects = map<string, object>
	
	def store(object):
	    id = sha1(object)
	    objects[id] = object
	
	def load(id):
	    return objects[id]
```
	- SHA-1 hash generates a fixed-size (40) hexadecimal(16进制) number.
- **References**
	- All snapshots can be identified by their SHA-1 hashes. But this is inconvenient for humans to read or remember.
	- References are pointers to commits.
		- `master`: the default name for the main branch
		- `HEAD`: the pointer to the current branch or commit, i.e. current working stage
		Unlike objects, which are immutable, references are mutable (can be updated to point to a new commit).
	```mathematica
		references = map<string, string>
```
- **Staging Area**:
	The staging area in Git, also known as the "index," is a place where changes are gathered before they are committed. It allows you to group file changes into coherent sets before committing them to the repository.
	- Concepts:
		1. Untracked Files: Files not added to the staging area yet.
		2. Tracked Files: Files that are already in the repository and being tracked by Git.
		3. Staged Changes: Changes that have been added to the staging area and are ready to be committed.
	- Basic Workflow:
		1. Modify Files: Make changes to your files.
		2. Stage Changes: `git add <file>` (or `git add .` to stage all changes).
		3. Commit Changes: `git commit -m "commit message"`
