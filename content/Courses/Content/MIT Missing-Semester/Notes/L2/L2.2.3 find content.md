- Finding files by name is useful, but quite often you want to search based on file _content_. 
- A common scenario is wanting to search for all files that contain some pattern, along with where in those files said pattern occurs. To achieve this, most UNIX-like systems provide [`grep`](https://www.man7.org/linux/man-pages/man1/grep.1.html), a generic tool for matching patterns from the input text.
	- Common flags:
		- `-C` for getting **C**ontext around the matching line
		- `-v` for in**v**erting the match, i.e. print all lines that do **not** match the pattern. 
	- But `grep -R` can be improved in many ways, such as ignoring `.git` folders, using multi CPU support, etc. Many `grep` alternatives have been developed, including [ack](https://github.com/beyondgrep/ack3), [ag](https://github.com/ggreer/the_silver_searcher) and [rg](https://github.com/BurntSushi/ripgrep).
	- Examples: `rg`"ripgrep"
		```bash
		# Find all python files where I used the requests library
		rg -t py 'import requests'
		# Find all files (including hidden files) without a shebang line
		rg -u --files-without-match "^#\!"
		# Find all matches of foo and print the following 5 lines
		rg foo -A 5
		# Print statistics of matches (# of matched lines and files )
		rg --stats PATTERN
		```
		- Note that as with `find`/`fd`, it is important that you know that these problems can be quickly solved using one of these tools, while the specific tools you use are not as important.
