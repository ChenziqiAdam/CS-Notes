Like other languages, logic has multiple dialects. We will introduce two: propositional logic and first-order logic. 

---
### Propositional Logic

- **Propositional logic** is written in sentences composed of **proposition symbols**, possibly joined by logical connectives. 
- A proposition symbol is generally represented as a single uppercase letter. Each proposition symbol stands for an atomic proposition about the world. 
- A **model** is an assignment of true or false to all the proposition symbols, which we might think of as a "possible world". 
	- For example, if we had the propositions A = "today it rained" and B = "I forgot my umbrella" then the possible models (or "worlds") are:
		1. {A=true, B=true} ("Today it rained and I forgot my umbrella.")
		2. {A=true, B=false} ("Today it rained and I didn’t forget my umbrella.")
		3. {A=false, B=true} ("Today it didn’t rain and I forgot my umbrella.")
		4. {A=false, B=false} ("Today it didn’t rain and I did not forget my umbrella.")
- In general, for N symbols, there are 2<sup>N</sup> possible models. We say a sentence is **valid** if it is true in all of these models (e.g. the sentence *True*), **satisfiable** if there is at least one model in which it is true, and **unsatisfiable** if it is not true in any models. 
	- For example, the sentence $A \land B$ is satisfiable because it is true in model 1, but not valid since it is false in models 2, 3, 4. 
	- On the other hand $\neg A \land A$ is unsatisfiable as no choice for A returns True.
- Below are some useful logical equivalences, which can be used for simplifying sentences to forms that are easier to work and reason with.
	![[Pasted image 20250627103309.png]]
- One useful syntax in propositional logic is the **conjunctive normal form** or **CNF** which is a conjunction of clauses, each of which a disjunction of literals.
	- It has the general form $(P_1 \lor ... \lor P_i) \land ... \land (P_j \lor ... \lor P_n)$, i.e. an AND of ORs
	- A sentence in this form is good for some analyses. Importantly, every logical sentence has a logically equivalent conjunctive normal form. 
	- This means that we can formulate all the information contained in our knowledge base (which is just a conjunction of different sentences) as one large CNF statement, by AND-ing these CNF statements together.

---
### Propositional Logical Inference

- Logic is useful and powerful because it grants the ability to draw new conclusions from what we already know. 
- To define the problem of inference we first need to define some terminology.
	- We say that a sentence $A$ **entails** another sentence $B$ if in all models that $A$ is true, $B$ is as well, and we represent this relationship as $A \models B$. 
	- Note that if $A \models B$ then the models of $A$ are a subset of the models of $B$, $M(A) \subseteq M(B)$. 
	- The inference problem can be formulated as figuring out whether $KB \models q$, where $KB$ is our knowledge base of logical sentences, and $q$ is some query. 
- We draw on two useful theorems to show entailment:
	1. $A \models B$ iff $A \Rightarrow B$ is valid
		- Proving entailment by showing that A ⇒B is valid is known as a **direct proof**.
	2. $A \models B$ iff $A \land \neg B$ is unsatisfiable
		- Proving entailment by showing that A ∧¬B is unsatisfiable is known as a **proof by contradiction**.

---
### Model Checking

- One simple algorithm for checking whether $KB \models q$ is to enumerate all possible models, and to check if in all the ones in which $KB$ is true, $q$ is true as well. 
	- This approach is known as **model checking**. 
	- In a sentence with a feasible number of symbols, enumeration can be done by drawing out a **truth table**.
- For a propositional logical system, if there are $N$ symbols, there are $2^N$ models to check, and hence the time complexity of this algorithm is $O(2^N)$, while in first-order logic, the number of models is infinite.
	- In fact the problem of propositional entailment is known to be co-NP-complete. 
	- While the worst case runtime will inevitably be an exponential function of the size of the problem, there are algorithms that can in practice terminate much more quickly. 
	- We will discuss two model checking algorithms for propositional logic.
#### DPLL

- The first, proposed by Davis, Putnam, Logemann, and Loveland (which we will call the **DPLL algorithm**) is essentially a depth-first, backtracking search over possible models with three tricks to reduce excessive backtracking. 
	- This algorithm aims to solve the satisfiability problem, i.e. given a sentence, find a working assignment to all the symbols. 
- As we mentioned, the problem of entailment can be reduced to one of satisfiability (show that $A \land \neg B$ is not satisfiable), and specifically DPLL takes in a problem in CNF. 
	- Satisfiability can be formulated as a constraint satisfaction problem as follows: let the variables (nodes) be the symbols and the constraints be the logical constraints imposed by the CNF. 
	- Then DPLL will continue assigning symbols truth values until either a satisfying model is found or a symbol cannot be assigned without violating a logical constraint, at which point the algorithm will backtrack to the last working assignment. 
- However, DPLL makes three improvements over simple backtracking search:
	1. **Early Termination**: 
		- A clause is true if any of the symbols are true. Therefore the sentence could be known to be true even before all symbols are assigned. 
		- Also, a sentence is false if any single clause is false. Early checking of whether the whole sentence can be judged true or false before all variables are assigned can prevent unnecessary meandering down subtrees.
	2. **Pure Symbol Heuristic**: 
		- A pure symbol is a symbol that only shows up in its positive form (or only in its negative form) throughout the entire sentence. 
		- Pure symbols can immediately be assigned true or false. For example, in the sentence $(A \lor B) \land (\neg B \lor C) \land (\neg C \lor A)$, we can identify $A$ as the only pure symbol and can immediately assign $A$ to true, reducing the satisfying problem to one of just finding a satisfying assignment of $(\neg B \lor C)$.
	3. **Unit Clause Heuristic**: 
		- A unit clause is a clause with just one literal or a disjunction with one literal and many falses. 
		- In a unit clause, we can immediately assign a value to the literal, since there is only one valid assignment. 
			- For example, B must be true for the unit clause $(B \lor false \lor ... \lor flase)$ to be true.
#### DPLL Example

- Suppose we have the following sentence in conjunctive normal form (CNF):
	$(\neg N \vee \neg S) \wedge (M \vee Q \vee N) \wedge (L \vee \neg M) \wedge (L \vee \neg Q) \wedge (\neg L \vee \neg P) \wedge (R \vee P \vee N) \wedge (\neg R \vee \neg L) \wedge (S)$
- We want to use the DPLL algorithm to determine whether it is satisfiable. 
	- Suppose we use a fixed variable ordering (alphabetical order) and a fixed value ordering (true before false). 
	- On each recursive call to the DPLL function, we keep track of three things::
		* $\text{model}$: A list of assigned symbols and their truth values (e.g., $\{A: T, B: F\}$).
		* $\text{symbols}$: A list of unassigned symbols.
		* $\text{clauses}$: A list of clauses (disjunctions) in CNF.
	- In other words, each call to DPLL is solving a smaller satisfiability problem, usually with fewer clauses, fewer symbols, and a model with some symbols already assigned.
##### Initial Call
- We start by calling DPLL with an empty model (no symbols assigned yet), symbols containing all the symbols in the original sentence, and clauses containing all the clauses in the original sentence.
- Initial DPLL:
	* $\text{model}$: \{\}
	* $\text{symbols}$: $[L, M, N, P, Q, R, S]$
	* $\text{clauses}$: $(\neg N \vee \neg S) \wedge (M \vee Q \vee N) \wedge (L \vee \neg M) \wedge (L \vee \neg Q) \wedge (\neg L \vee \neg P) \wedge (R \vee P \vee N) \wedge (\neg R \vee \neg L) \wedge (S)$
##### Step 1: Process Unit Clause (S)
* Early termination check: Not applicable yet.
* Pure literal heuristic: No pure literals found.
* Unit clause heuristic: $(S)$ is a unit clause. Therefore, $S$ must be $\text{True}$.
* Second DPLL:
    * $\text{model}$: $\{S: T\}$
    * $\text{symbols}$: $[L, M, N, P, Q, R]$
    * $\text{clauses}$ (simplified by $S=T$, so $\neg S=F$): $(\neg N) \wedge (M \vee Q \vee N) \wedge (L \vee \neg M) \wedge (L \vee \neg Q) \wedge (\neg L \vee \neg P) \wedge (R \vee P \vee N) \wedge (\neg R \vee \neg L)$
##### Step 2: Process Unit Clause ($\neg N$)
* Early termination check: Not applicable yet.
* Pure literal heuristic: No pure literals found.
* Unit clause heuristic: $(\neg N)$ is a unit clause. Therefore, $N$ must be $\text{False}$.
* Third DPLL:
    * $\text{model}$: $\{S: T, N: F\}$
    * $\text{symbols}$: $[L, M, P, Q, R]$
    * $\text{clauses}$ (simplified by $N=F$, so $N=F$, $\neg N=T$): $(M \vee Q) \wedge (L \vee \neg M) \wedge (L \vee \neg Q) \wedge (\neg L \vee \neg P) \wedge (R \vee P) \wedge (\neg R \vee \neg L)$
##### Step 3: Branch on M (first unassigned symbol alphabetically)
* Early termination check: Not applicable.
* Pure literal heuristic: Not found.
* Unit clause heuristic: Not found.
* Since no more simplifications are possible, we pick the first unassigned symbol, $M$, and try $M = \text{True}$ first.
##### Branch A: Assume M = True
* **Resulting Call**:
    * $\text{model}$: $\{S: T, N: F, M: T\}$
    * $\text{symbols}$: $[L, P, Q, R]$
    * $\text{clauses}$ (simplified by $M=T$, so $M=T$, $\neg M=F$): $(L) \wedge (L \vee \neg Q) \wedge (\neg L \vee \neg P) \wedge (R \vee P) \wedge (\neg R \vee \neg L)$
###### Step 3A.1: Process Unit Clause (L) and Pure Literal (Q)
* Early termination check: Not applicable.
* Pure literal heuristic: $Q$ is a pure literal (appears only as $\neg Q$). Assign $Q = \text{False}$ to make $\neg Q$ true.
* Unit clause heuristic: $(L)$ is a unit clause. Therefore, $L$ must be $\text{True}$.
* **Resulting Call (after Q=F and L=T)**:
    * $\text{model}$: $\{S: T, N: F, M: T, Q: F, L: T\}$
    * $\text{symbols}$: $[P, R]$
    * $\text{clauses}$ (simplified by $Q=F$ and $L=T$): $(\neg P) \wedge (R \vee P) \wedge (\neg R)$
###### Step 3A.2: Process Unit Clauses ($\neg P$) and ($\neg R$)
* Early termination check: Not applicable.
* Pure literal heuristic: Not found.
* Unit clause heuristic: $(\neg P)$ is a unit clause. Therefore, $P$ must be $\text{False}$. Also, $(\neg R)$ is a unit clause, so $R$ must be $\text{False}$.
* **Resulting Call (after P=F and R=F)**:
    * $\text{model}$: $\{S: T, N: F, M: T, Q: F, L: T, P: F, R: F\}$
    * $\text{symbols}$: $[ ]$
    * $\text{clauses}$ (simplified by $P=F$ and $R=F$): $(R) \wedge (\neg R)$
###### Step 3A.3: Contradiction Found
* Early termination check: The clauses $(R)$ and $(\neg R)$ cannot both be true simultaneously.
* **Conclusion**: This branch ($M=\text{True}$) leads to an unsatisfiable sentence.

##### Branch B: Backtrack and Assume M = False
* Since the $M=\text{True}$ branch failed, we backtrack and try $M = \text{False}$.
* **Resulting Call**:
    * $\text{model}$: $\{S: T, N: F, M: F\}$
    * $\text{symbols}$: $[L, P, Q, R]$
    * $\text{clauses}$ (simplified by $M=F$): $(Q) \wedge (L \vee \neg Q) \wedge (\neg L \vee \neg P) \wedge (R \vee P) \wedge (\neg R \vee \neg L)$
###### Step 3B.1: Process Unit Clause (Q)
* Early termination check: Not applicable.
* Pure literal heuristic: Not found.
* Unit clause heuristic: $(Q)$ is a unit clause. Therefore, $Q$ must be $\text{True}$.
* **Resulting Call**:
    * $\text{model}$: $\{S: T, N: F, M: F, Q: T\}$
    * $\text{symbols}$: $[L, P, R]$
    * $\text{clauses}$ (simplified by $Q=T$): $(L) \wedge (\neg L \vee \neg P) \wedge (R \vee P) \wedge (\neg R \vee \neg L)$
###### Step 3B.2: Process Unit Clause (L)
* Early termination check: Not applicable.
* Pure literal heuristic: Not found.
* Unit clause heuristic: $(L)$ is a unit clause. Therefore, $L$ must be $\text{True}$.
* **Resulting Call**:
    * $\text{model}$: $\{S: T, N: F, M: F, Q: T, L: T\}$
    * $\text{symbols}$: $[P, R]$
    * $\text{clauses}$ (simplified by $L=T$): $(\neg P) \wedge (R \vee P) \wedge (\neg R)$
###### Step 3B.3: Process Unit Clauses ($\neg P$) and ($\neg R$)
* Early termination check: Not applicable.
* Pure literal heuristic: Not found.
* Unit clause heuristic: $(\neg P)$ is a unit clause. Therefore, $P$ must be $\text{False}$. Also, $(\neg R)$ is a unit clause, so $R$ must be $\text{False}$.
* **Resulting Call (after P=F and R=F)**:
    * $\text{model}$: $\{S: T, N: F, M: F, Q: T, L: T, P: F, R: F\}$
    * $\text{symbols}$: $[ ]$
    * $\text{clauses}$ (simplified by $P=F$ and $R=F$): $(R) \wedge (\neg R)$
###### Step 3B.4: Contradiction Found
* Early termination check: The clauses $(R)$ and $(\neg R)$ cannot both be true simultaneously.
* **Conclusion**: This branch ($M=\text{False}$) also leads to an unsatisfiable sentence.
##### Final Conclusion
Since both branches ($M=\text{True}$ and $M=\text{False}$) resulted in unsatisfiable sentences, the entire original sentence is unsatisfiable.

#### Theorem Proving

- An alternate approach is to apply rules of inference to $KB$ to prove that $KB \models p$. 
	- For example, if our knowledge base contains $A$ and $A \implies B$ then we can infer $B$ (this rule is known as *ModusPonens*). The two previously mentioned algorithms use the fact ii.) by writing $A \land \neg B$ in CNF and show that it is either satisfiable or not.
- We could also prove entailment using three rules of inference:
	1. If our knowledge base contains $A$ and $A \implies B$ we can infer $B$ (**Modus Ponens**).
	2. If our knowledge base contains $A \land B$ we can infer $A$. We can also infer $B$. (**And-Elimination**).
	3. If our knowledge base contains $A$ and $B$ we can infer $A \land B$ (**Resolution**).
- The last rule forms the basis of the **resolution algorithm** which iteratively applies it to the knowledge base and to the newly inferred sentences until either $q$ is inferred, in which case we have shown that $KB \not\models q$, or there is nothing left to infer, in which case $KB \not\models q$. 
	- Although this algorithm is both sound (the answer will be correct) and complete (the answer will be found) it runs in worst case time that is exponential in the size of the knowledge base.
- However, in the special case that our knowledge base only has literals (symbols by themselves) and implications: $(P_1 \land ... \land P_n \implies Q) \equiv (\neg P_1 \lor ... \lor \neg P_2 \lor Q)$, we can prove entailment in time linear to the size of the knowledge base. 
	- One algorithm, **forward chaining** iterates through every implication statement in which the **premise** (left hand side) is known to be true, adding the **conclusion** (right hand side) to the list of known facts. This is repeated until q is added to the list of known facts, or nothing more can be inferred.
#### Forward Chaining Example

- Suppose we had the following knowledge base:
	1. $A \rightarrow B$
	2. $A \rightarrow C$
	3. $B \wedge C \rightarrow D$
	4. $D \wedge E \rightarrow Q$
	5. $A \wedge D \rightarrow Q$
	6. $A$
	- We want to determine if $Q$ is true.
- We initialize three data structures:
	* `count`: A list where `count[i]` stores the number of unknown symbols in the premise of the $i$-th clause.
	* `inferred`: A dictionary mapping each symbol to a boolean indicating whether it has been proven true. Initially, all are `False`.
	* `agenda`: A queue of symbols that have been newly proven true but whose consequences have not yet been propagated.
##### Initial State
* `count`: $[1, 1, 2, 2, 2, 0]$ (e.g., clause 1 ($A \rightarrow B$) has 1 premise, clause 3 ($B \wedge C \rightarrow D$) has 2 premises, clause 6 ($A$) has 0 premises (equivalent to $True \rightarrow A$))
* `inferred`: $\{A: F, B: F, C: F, D: F, E: F, Q: F\}$
* `agenda`: $[A]$ (from clause 6, $A$ is initially known to be true)
##### Iteration 0: Pop A from Agenda
1. Pop `A` from `agenda`. (`A` is not `Q`).
2. Set `inferred[A]` to `True`.
3. Propagate consequences of `A` being true:
    * Decrement `count` for clauses where `A` is in the premise (clauses 1, 2, and 5).
        * `count`: $[0, 0, 2, 2, 1, 0]$
    * Check if any `count` has reached 0.
        * Clause 1 (`A \rightarrow B`): `count[0]` is now 0. Add `B` to `agenda`.
        * Clause 2 (`A \rightarrow C`): `count[1]` is now 0. Add `C` to `agenda`.
* **State after Iteration 0**:
    * `count`: $[0, 0, 2, 2, 1, 0]$
    * `inferred`: $\{A: T, B: F, C: F, D: F, E: F, Q: F\}$
    * `agenda`: $[B, C]$
##### Iteration 1: Pop B from Agenda
1. Pop `B` from `agenda`. (`B` is not `Q`).
2. Set `inferred[B]` to `True`.
3. Propagate consequences of `B` being true:
    * Decrement `count` for clauses where `B` is in the premise (clause 3).
        * `count`: $[0, 0, 1, 2, 1, 0]$
    * Check if any `count` has reached 0. (None newly reached 0).
* **State after Iteration 1**:
    * `count`: $[0, 0, 1, 2, 1, 0]$
    * `inferred`: $\{A: T, B: T, C: F, D: F, E: F, Q: F\}$
    * `agenda`: $[C]$
##### Iteration 2: Pop C from Agenda
1. Pop `C` from `agenda`. (`C` is not `Q`).
2. Set `inferred[C]` to `True`.
3. Propagate consequences of `C` being true:
    * Decrement `count` for clauses where `C` is in the premise (clause 3).
        * `count`: $[0, 0, 0, 2, 1, 0]$
    * Check if any `count` has reached 0.
        * Clause 3 (`B \wedge C \rightarrow D`): `count[2]` is now 0. Add `D` to `agenda`.
* **State after Iteration 2**:
    * `count`: $[0, 0, 0, 2, 1, 0]$
    * `inferred`: $\{A: T, B: T, C: T, D: F, E: F, Q: F\}$
    * `agenda`: $[D]$
##### Iteration 3: Pop D from Agenda
1. Pop `D` from `agenda`. (`D` is not `Q`).
2. Set `inferred[D]` to `True`.
3. Propagate consequences of `D` being true:
    * Decrement `count` for clauses where `D` is in the premise (clauses 4 and 5).
        * `count`: $[0, 0, 0, 1, 0, 0]$
    * Check if any `count` has reached 0.
        * Clause 5 (`A \wedge D \rightarrow Q`): `count[4]` is now 0. Add `Q` to `agenda`.
* **State after Iteration 3**:
    * `count`: $[0, 0, 0, 1, 0, 0]$
    * `inferred`: $\{A: T, B: T, C: T, D: T, E: F, Q: F\}$
    * `agenda`: $[Q]$
##### Iteration 4: Pop Q from Agenda
1. Pop `Q` from `agenda`. (`Q` is the query symbol).
2. Since `Q` was popped from the agenda, it has been proven true.
* **Conclusion**: $Q$ is true. The algorithm terminates.
