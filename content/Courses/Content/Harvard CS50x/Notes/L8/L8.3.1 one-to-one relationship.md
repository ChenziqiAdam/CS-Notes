- Duplicating numbers are more welcome than duplicating strings. 
	Numbers are easier for computers to operate on than strings.
	- **Hashing!**
- There are usually multiple relationships between tables.

- **More keywords**:
	- `NOT NULL`: better protection for the database
	- `UNIQUE`: avoid duplicates
- More features of relational databases
	with multiple tables with relationships
	- `PRIMARY KEY`(主键): number->string, i.e. id->show
	- `FOREIGN KEY`(外键)
		`FOREIGN KEY` is the presence of `PRIMARY KEY` in some other tables, which links two tables together.
	- Example:
		```SQL
		CREATE TABLE shows (
		    id INTEGER,
		    title TEXT NOT NULL,
		    year NUMERIC,
		    episodes INTEGER,
		    PRIMARY KEY(id)
		);
		CREATE TABLE ratings (
		    show_id INTEGER NOT NULL,
		    rating REAL NOT NULL,
		    votes INTEGER NOT NULL,
		    FOREIGN KEY(show_id) REFERENCES shows(id)
		);
```
	- e.g.
		```SQL
		SELECT * FROM shows WHERE id IN 
		(SELECT show_id FROM ratings WHERE rating >= 6.0 LIMIT 10);
```
		- Nested Query!
- **More keywords**:
	`JOIN`: <u>join two tables together</u>
	- e.g. 
		```SQL
		SELECT title, rating FROM shows
		JOIN ratings ON shows.id = ratings.show_id WHERE rating >= 6.0 LIMIT 10;
	```
		`.` notation is simply about column
