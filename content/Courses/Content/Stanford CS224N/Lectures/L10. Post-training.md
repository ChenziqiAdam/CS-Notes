## Zero-Shot and Few-Short

- **Zero-Shot**(**ZS**): the ability to do many tasks with no examples, and no gradient updates
	```
	Translate English to French:
	cheese =>
	```
- **Few-Shot**(**FS**): 
	- Specify a task by simply prepending examples of the task before your example
	- Also called **in-context learning**, to stress that *no gradient updates* are performed when learning a new task
	```
	Translate English to French:
	sea otter => loutre de mer
	peppermint => menthe poivrée
	plush girafe => girafe peluche
	cheese =>
	```
- **Chain-of-thought**(**CoT**)
	- Some tasks seem too hard for even large LMs to learn through prompting alone. Especially tasks involving richer, multi-step reasoning.
	- Add examples of reasoning
	```
	Q: Roger has 5 tennis balls. He buys 2 more cans of
	tennis balls. Each can has 3 tennis balls. How many
	tennis balls does he have now?
	
	A: Roger started with 5 balls. 2 cans of 3 tennis balls
	each is 6 tennis balls. 5 + 6 = 11. The answer is 11.
	
	Q: The cafeteria had 23 apples. If they used 20 to
	make lunch and bought 6 more, how many apples
	do they have?
	```
	- Can simply add "*Let's think step by step*".
- All these falls in the category of **Prompt Engineering**.
- Limitations:
	- Limits to what you can fit in context 
	- Complex tasks will probably need gradient steps

## Instruction Finetuning

- Problem: Language models are not aligned with user intent.
- Solution: Finetune the model with **instruction-answer pairs**.
- Limitations
	- Expensive to collect ground-truth data for tasks.
	- Tasks like open-ended creative generation have no right answer.
	- Language modeling penalizes all token-level mistakes equally, but some errors are worse than others.
	- Humans generate suboptimal answers

## Optimizing for human preferences
### RLHF: RL from Human Feedback

- Goal: We want to maximize the expected reward of samples from our language model:
	$\mathbb{E}_{\hat{y} \sim p_\theta(y|x)}[R(x, \hat{y})]$
- RLHF Pipeline
	![[Pasted image 20251117105017.png]]
- Q. The key problem is that how to get the rewards?
	- Train a reward model $RM_\phi(x, y)$ to predict human reward from an annotated dataset, then optimize for $RM_\phi$ instead.
	- Instead of asking for direct ratings, ask for **pairwise comparisons** which can be more reliable.
	- Bradley-Terry paired comparison model
		$J_{\text{RM}}(\phi) = -\mathbb{E}_{(x, y^w, y^l) \sim D} \left[ \log \sigma \left( RM_\phi(x, y^w) - RM_\phi(x, y^l) \right) \right]$
		- $y^w$ is the "winning" sample.
		- $y^l$ is the "losing" sample.
		- $y^w$ should score higher than $y^l$.
- **Reinforcement Learning from Human Feedback** (**RLHF**)
	- Now we have the following:
		- A pretrained (possibly instruction-finetuned) language model $p^{PT}(y|x)$.
		- A reward model $RM_\phi(x, y)$ that produces scalar rewards for language model outputs, trained on a dataset of human comparisons.
	- Now to do RLHF:
		- Copy the model $p_\theta^{RL}(y|x)$, with parameters $\theta$ we would like to optimize.
		- We want to optimize:
			$\mathbb{E}_{\hat{y} \sim p_\theta^{RL}(\hat{y}|x)} \left[ RM_\phi(x, \hat{y}) \right]$
	- Note: Learned rewards are imperfect; this quantity can be imperfectly optimized
	- Add a penalty for drifting too for from the initialization:
		$\mathbb{E}_{\hat{y} \sim p_\theta^{RL}(\hat{y}|x)} \left[ RM_\phi(x, \hat{y}) - \beta \log \left( \frac{p_\theta^{RL}(\hat{y}|x)}{p^{PT}(\hat{y}|x)} \right) \right]$
		- We know the initial model is quite decent.
		- This penalty, which prevents us from diverging too far from the pretrained model, is known in expectation as the **Kullback-Leibler (KL) divergence** between $p_\theta^{RL}(\hat{y}|x)$ and $p^{PT}(\hat{y}|x)$.
			- i.e. pay a price when $p_\theta^{RL}(\hat{y}|x) > p^{PT}(\hat{y}|x)$
	- General Idea:
		- Generate completions from $p_\theta^{RL}$ for several tasks.
		- Compute reward using $RM_\phi(x, y)$.
		- Update $p_\theta^{RL}(y|x)$ to increase the probability of high-reward completions.

### DPO: Direct Preference Optimization

- Problem with RLHF: RL optimization can be computationally expensive and complicated.
	- Current RLHF Pipeline:
		- Train a reward model $RM_\phi(x, y)$ to produce scalar rewards for language model outputs, trained on a dataset of human comparisons.
		- Optimize the pretrained (possibly instruction-finetuned) language model $p^{PT}(y|x)$ to produce the final RLHF language model $p_\theta^{RL}(\hat{y}|x)$.
	- Q. What if we could express $RM_\phi(x, y)$ in terms of $p_\theta^{RL}(\hat{y}|x)$?
		- Derive $RM_\theta(x, y)$ in terms of $p_\theta^{RL}(\hat{y}|x)$.
		- Optimize parameters $\theta$ by fitting $RM_\theta(x, y)$ to the preference data instead of $RM_\phi(x, y)$.
	- Note: The only external information to the optimization comes from the preference labels
- **Direct Preference Optimization**(**DPO**):
	- Recall:
		- Objective: Maximize the following expectation:
			$\mathbb{E}_{\hat{y} \sim p_\theta^{RL}(\hat{y}|x)} \left[ RM(x, \hat{y}) - \beta \log \left( \frac{p_\theta^{RL}(\hat{y}|x)}{p^{PT}(\hat{y}|x)} \right) \right]$
		- Closed form solution:
			$p^*(\hat{y}|x) = \frac{1}{Z(x)} p^{PT}(\hat{y}|x) \exp \left( \frac{1}{\beta} RM(x, \hat{y}) \right)$
		- Rearranged:
			$RM(x, \hat{y}) = \beta \log \frac{p^*(\hat{y}|x)}{p^{PT}(\hat{y}|x)} + \beta \log Z(x)$
		- Generalized for arbitrary LMs:
			$RM_\theta(x, \hat{y}) = \beta \log \frac{p_\theta^{RL}(\hat{y}|x)}{p^{PT}(\hat{y}|x)} + \beta \log Z(x)$
	- Recall: The reward model $RM_\phi(x, y)$ is fit using:
		$J_{RM}(\phi) = -\mathbb{E}_{(x, y^w, y^l) \sim D} \left[ \log \sigma \left( RM_\phi(x, y^w) - RM_\phi(x, y^l) \right) \right]$
	- Notice that only the difference between rewards for $y^w$ and $y^l$ is needed. Simplify for $RM_\theta(x, y)$:
		$RM_\theta(x, y^w) - RM_\theta(x, y^l) = \beta \log \frac{p_\theta^{RL}(y^w|x)}{p^{PT}(y^w|x)} - \beta \log \frac{p_\theta^{RL}(y^l|x)}{p^{PT}(y^l|x)}$
	- Final DPO Loss Function (remove $Z(x)$):
		$J_{DPO}(\theta) = -\mathbb{E}_{(x, y^w, y^l) \sim D} \left[ \log \sigma \left( \beta \log \frac{p_\theta^{RL}(y^w|x)}{p^{PT}(y^w|x)} - \beta \log \frac{p_\theta^{RL}(y^l|x)}{p^{PT}(y^l|x)} \right) \right]$
	- We have a simple classification loss function that connects preference data to language model parameters directly!

## Summary

- We want to optimize for human preferences
	- Instead of humans writing the answers or giving uncalibrated scores, we get humans to rank different LM generated answers
- Reinforcement learning from human feedback
	- Train an explicit reward model on comparison data to predict a score for a given completion
	- Optimize the LM to maximize the predicted score (under KL-constraint)
	- Very effective when tuned well, computationally expensive and tricky to get right
- Direct Preference Optimization
	- Optimize LM parameters directly on preference data by solving a binary classification problem
	- Simple and effective, similar properties to RLHF, does not leverage online data
