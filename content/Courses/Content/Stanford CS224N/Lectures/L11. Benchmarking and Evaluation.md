## Different Consideration for Measuring Performance

1. Train
	- Super fast and cheap
	- Differentiable (backpropagation)
	- No shortcut (model hack)
2. Develop
	- Super fast and cheap
	- Avoid shortcut
3. Model selection
	- Fast and cheap
4. Publish
	- Standardized
	- Reproducible
	- Easy to work with
	- Broad coverage
	- Fine-grained distinguishability (neither too easy nor too difficult)
5. Deploy
	- Trustworthy
	- Task-specific
	- Absolute

## Close-ended Evaluation

- Close-ended tasks
	- Limited number of potential answers
	- One or just a few correct answers
	- Enable automatic evaluation as in ML (nothing special about NLP)
- Examples
	- Sentiment analysis
	- Entailment(包含关系)
	- Name entity recognition
	- Coreference resolution
	- QA
- Challenges
	- How to choose the metrics? accuracy / precision / recall / F1 / ROC / AUC
	- How to aggregate across metrics or tasks
	- Where do the labels come from?
	- Are these spurious(虚假的) correlations?

## Open-ended Evaluation

- Open-ended tasks
	- Too many possible correct answers to enumerate
	- No just right or wrong, but better and worse
- **Content Overlap Metrics**
	- Compute a score that indicates the lexical similarity between generated and gold- standard (human-written) text
	- N-gram overlap metrics (e.g., BLEU, ROUGE, etc.)
		- Not ideal but often still reported for translation (BLEU) and summarization (ROUGE)
- **Model-based Metrics**
	- Use learned representations of words and sentences to compute semantic similarity between generated and reference texts
		- Vector similarity
		- BERTScore
		- BLEURT
	- Note: Reference-based measures are only as good as their references.
- **Reference-free Evals**
	- Reference-based evaluation:
		- Compare human written reference to model outputs
		- Used to be 'standard' evaluation for most NLP tasks
			- e.g. BLEU, ROUGE, BertScore etc.
	- Reference free evaluation
		- Have a model give a score
		- No human reference
		- Was nonstandard - now becoming popular with GPT4
			- e.g. AlpacaEval, MT-Bench
- **Human Evaluations**
	- Automatic metrics fall short of matching human decisions
	- Human evaluation is most important form of evaluation for text generation.
	- Gold standard in developing new automatic metrics
		- New automated metrics must correlate well with human evaluation
	- Note: Don't compare human evaluation scores across differently conducted studies.
	- Issues:
		- Slow and expensive
		- Inter-annotator disagreement (subjective)
		- Not reproducible
		- Precision not recall
		- Biases/shortcuts if incentives not aligned
	- Challenges
		- How to describe the task?
		- How to show the task to the humans?
		- Selecting the annotators
		- Monitoring the annotators: time, accuracy, ...
- **Reference-free Evals**: Chatbots
	- Q. So many different use cases it's hard to evaluate. The responses are also long-form text, which is even harder to evaluate.
	- **Side-by-side ratings**
		- e.g. Chatbot Arena (Invite people to use models free online and select the better choice)
	- Issues
		- Human annotation takes large, community effort
		- New models take a long time to benchmark
		- Only notable models get benchmarked

## Challenges

- **Consistency:**
	- Different prompt
	- Different generation
		- Probability / Generated answer
- **Contamination and Overfitting**: Solutions
	- Control the number of times one can see the test set
	- Dynamic test set
	- Detector
		![[Pasted image 20260206113134.png]]
- **Monoculture of Benchmarking**
	- Mostly on English and performance
- **Single Metric**
	- Performance is not all we care about
		- Computational efficiency
		- Biases
		- Preferences
- **Biases**
	- Minoritized groups
	- Mostly west languages which can be applied with BLEU
		- Academic researchers are incentivized to keep using the same benchmark to compare to previous work
	- Opinions and values
	- LLM-based evaluations
