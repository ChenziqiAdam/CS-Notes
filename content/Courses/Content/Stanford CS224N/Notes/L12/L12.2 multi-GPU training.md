- The optimizer stores its parameters on GPU VRAM.
	- E.g. Adam Optimizer
		- Master weights (FP32)
		- Adam momentum (FP32)
		- Adam variance (FP32)

## ZeRO Stage 1

- Idea: Instead of letting every GPU maintain all of the states, lets shard the states.
- Optimizer State Sharding: Only update part of the optimizer state
	![[Pasted image 20260226161045.png]]
	- Each GPU has the full set of FP16 model parameters, and computes the gradient on its subset of data
	- Each GPU has a sharded copy of the full optimizer state.
	- Each GPU is responsible for updating a shard of the full parameters
- MPI Operation: **Reduce-Scatter** and **All-Gather**
	![[Pasted image 20260226161306.png]]
- All-Reduce = Reduce-Scatter + All-Gather (But the righthand side uses less memory for free!)
	![[Pasted image 20260226161453.png]]

## ZeRO Stage 2

- Optimizer State + Gradient Sharding
	![[Pasted image 20260226161934.png]]
- Q. Along with sharing optimizer state, can we also shard gradients? We still need the full gradient for the worker’s data slice!
- A. Never instantiate the full gradient vector! Send gradient to the “GPU in charge” as soon as the gradient for a shard is made available in the backward pass.
	- Worker performs a backward pass layer-by-layer in the computation graph
	- Suppose worker is at layer-j:
		- Take upstream gradient, compute gradient for parameters at layer-j, immediately send the gradients to the correct worker (reduce)
		- Deallocate memory for parameter gradient.
	- Worker updates its param shard using corresponding gradient + state. Perform an all-gather to synchronize

## ZeRO Stage 3 (Full FSDP)

- So far, communication overhead was ”free”. With Full FSDP (Fully Shard Data Parallel), this is no longer the case.
- Q. When even the model parameters won't fit on a single GPU?
	![[Pasted image 20260226162548.png]]
- High-level sketch:
	1. Divide model parameters into FSDP units (architecture specific)
		![[Pasted image 20260227173201.png]]
	2. Shard each unit across multiple GPUs
		![[Pasted image 20260227173224.png]]
	3. Run forward pass:
		- Perform an all-gather so each GPU gets all pieces of a module.
		- Run forward pass
		- Discard param shards
	4. Run backward pass:
		- Perform an all-gather to get all pieces of module,
		- Each GPU computes gradient for its data chunk
		- Do a reduce-scatter to send full gradient piece to the right GPU
	5. Each GPU updates its own shard using the full gradient received earlier.
	![[Pasted image 20260226163005.png]]
	- Diagram Explanation: Overlap operations to take full advantage of GPU memories
		- 0, 1, 2 are different FSDP units
		- AG0: all-gather to get the full set parameters of first layer, i.e. layer 0 by communication
		- Prefetch the next FSDP units before the beginning of AG1
		- If not enough memory, free some in the yellow parts
